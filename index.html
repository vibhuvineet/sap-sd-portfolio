S/4HANA Knowledge

SAP S/4HANA — Key Transformations & Modern Capabilities

BP.001
Business Partner Migration
In S/4HANA, legacy Customer (KNA1/KNB1) tables are replaced by the centralised Business Partner (BUT000) object. Customer-vendor integration is handled through BP roles — eliminating redundancy and simplifying master data governance. The CVI synchronisation tool handles migration from ECC.
BP RolesBUT000CVI SyncMigration
ATP.002
Advanced ATP (aATP)
aATP replaces classic GATP in S/4HANA. It introduces Backorder Processing (BOP), Product Allocation (PA), and Confirmation Strategy — enabling rule-based confirmation logic and priority-driven order fulfilment against constrained stock. Replaces OVZ9-based configuration.
BOPProduct AllocationConfirmation Rules
RAR.003
Revenue Accounting (IFRS 15)
SAP RAR implements the IFRS 15 / ASC 606 five-step revenue recognition model. SD billing documents post to RAR, where Performance Obligations (POBs), Standalone Selling Prices (SSPs), and contract modifications are managed separately from standard FI posting.
IFRS 15POBsSSPRAR
OUT.004
BRF+ Output Management
Classic NACE condition-based output is replaced by SAP BRF+ in S/4HANA. Output conditions and determination rules are maintained as decision tables in BRF+, offering greater flexibility and separation from ABAP. Forms connect via output items in Adobe Forms or Smart Forms.
BRF+Decision TablesAdobe Forms
FIO.005
SAP Fiori & Simplifications
S/4HANA replaces many SAPGUI transactions with Fiori apps. Key SD Fiori apps include Manage Sales Orders, Create Billing Documents, and Monitor ATP Situation. The S/4HANA Simplification List is the essential reference for deprecated transactions and migration paths for each.
Fiori AppsSimplification ListSAPGUI → Fiori
MIG.006
ECC → S/4HANA Migration
Three migration paths: Greenfield (new implementation), Brownfield (system conversion using SUM/DMLT), and Selective Data Migration. Each has distinct implications for SD customising, BAdIs, user exits, pricing routines, and master data structures including Business Partner and material master.
GreenfieldBrownfieldSUM ToolData Migration

Pre-Sales Activities
Inquiries · Quotations · Contracts
Pre-sales covers Inquiries (VA11) and Quotations (VA21) — reference documents that feed downstream into Sales Orders. Outline Agreements (contracts VA41 and scheduling agreements VA31) define long-term supply relationships. Copy control routines (VTAA/VTLA) govern data flow between document types, including pricing carry-forward and quantity referencing.
Key T-Codes
VA11, VA21, VA41, VA31
Config Objects
Copy Control VTAA, Partner Determination, Pricing
Key Concepts
Document Flow, Reason for Rejection, Target Qty, Validity Dates
Sales Order Processing
Pricing · Credit Check · ATP · Partner Det.
The Sales Order (VA01) is the central O2C document. At creation, SAP simultaneously executes Pricing (OVKK procedure), Credit Management (FD32/OVA8), Availability Check (OVZZ — checking rule + business event), Material Determination, Output Determination, and Partner Determination. Item categories (VOV7) and schedule line categories (VOV6) drive fulfilment logic — controlling delivery relevance, billing relevance, and MRP planning.
Key T-Codes
VA01, VA02, VA05, V.26, VD52
Config Objects
Sales Doc Type VOV8, Item Category VOV7, Schedule Line VOV6
Key Tables
VBAK (header), VBAP (item), VBEP (schedule line)
Delivery Processing
VL01N · Picking · Packing · Route Det.
Outbound Deliveries (LF doc type) are created via VL01N or the delivery due list (VL10A/VL10B). Picking (WM/EWM), packing (HU management), weight/volume determination, and route determination occur here. Delivery item categories control GI relevance, packing, and billing relevance. Shipping condition and route drive carrier and transit time calculation.
Key T-Codes
VL01N, VL02N, VL10A, VL10B, VL04
Config Objects
Delivery Type OVLK, Delivery Item Category, Copy Control VTLA
Key Tables
LIKP (delivery header), LIPS (delivery item)
Post Goods Issue
VL02N · Mvt Type 601 · FI Impact
Post Goods Issue (PGI) via VL02N triggers Movement Type 601 — reducing stock and creating a Material Document (MKPF/MSEG) and FI document simultaneously. PGI is the legal point of ownership transfer. The actual GI date drives billing date determination and revenue recognition timing in RAR/IFRS 15. Reversal uses movement type 602.
Key T-Codes
VL02N, MB51, MMBE (stock overview)
Movement Type
601 — GI for Sales Order; 602 — Reversal
FI Posting
Dr COGS / Cr Inventory — via Account Keys GBB / VAX
Billing & Invoice Processing
VF01 · Billing Plans · Intercompany · Rebates
Billing documents (F2, LR, RE, G2, L2) are created from delivery or order. Billing Type (VOFA) controls document class, account determination, and output. Billing Plans support project or subscription billing. Intercompany billing (IV) creates internal invoices between company codes. Copy control VTFL/VTFA controls pricing carry-over and re-pricing behaviour.
Key T-Codes
VF01, VF04, VF11, VOFA, VBO1 (rebates)
Config Objects
Billing Type VOFA, Copy Control VTFL / VTFA
Key Tables
VBRK (billing header), VBRP (billing item)
FI Account Determination & Cash Receipt
VKOA · Account Keys · Open Item Clearing
Billing release creates an FI document via Account Determination (VKOA). Condition types carry Account Keys — ERL for revenue, ERS for sales deductions, ERF for freight. The G/L account is derived from Chart of Accounts + Account Assignment Group (Customer + Material) + Account Key. Customer payment is matched against the open AR item in F-28 or cleared via F-32.
Key T-Codes
VKOA, VF02 (release), F-28, F-32
Account Keys
ERL (revenue), ERS (deductions), ERF (freight), MWS (tax)
Key Tables
T030 (G/L), BSID (open items), BKPF (FI doc header)

Advanced Pricing
Condition Technique Architecture
Pricing Procedure (OVKK) → Condition Types (V/06) → Access Sequences (V/07) → Condition Tables. Step/Counter logic drives calculation order. Requirement and alternative calculation routines in VOFM control when a condition fires and how its value is derived at runtime.
Rebate Processing
Agreements & Settlement
Rebate agreements (VBO1) accumulate accruals against billing documents throughout the validity period. Partial or final settlement creates a credit memo request. Condition types B001–B004 handle standard rebate scenarios. Retroactive pricing requires special handling in S/4HANA's RAR environment.
VOFM Routines
Custom Pricing Logic
VOFM is the repository for Requirements, Formulas, and Base Value routines. Custom ABAP routines enable dynamic pricing — calculating condition values based on weight, calendar dates, customer classification, or runtime variables — extending far beyond standard condition records.
